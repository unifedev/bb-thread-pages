# 04 — The page runtime

What an agent authoring a page can rely on. This is the entire page-facing
surface; nothing else about the host is visible from inside a page (P4).

## The kernel

The host injects a small script into the document before any authored script
runs. It provides form capture, the dirty flag, and `window.threadPage`.

- **R4.1** The kernel MUST be injected ahead of all authored scripts, so a page
  may use `window.threadPage` at parse time.
- **R4.2** Injection MUST NOT disturb the authored document: no reformatting, no
  reordering, no rewriting of authored URLs, and no `<base>` pointing off-origin.
- **R4.3** `window.threadPage` MUST be non-writable and non-configurable, so one
  script cannot shim it for another.
- **R4.4** The kernel MUST NOT depend on the document being well-formed. A
  malformed document MUST still get a working kernel where the parser allows.

## Forms

The central affordance: a plain `<form>` answers the reader's session with no
JavaScript at all.

- **R4.5** Every `<form>` in the document MUST be captured by the host and
  delivered as a message to the owning session, **unless** it carries an opt-out
  attribute.
- **R4.6** A form carrying the opt-out attribute MUST be left entirely alone.
- **R4.7** Multiple forms MUST have independent pending, dirty, and status state.
- **R4.8** While a submission is in flight, that form's controls MUST be disabled
  and a status line MUST be shown. On completion the status MUST say whether it
  was delivered or queued, or why it failed.
- **R4.9** Native validation MUST be suppressed on captured forms. A blank answer
  is a real answer and MUST be deliverable.

### Answer naming

The reader sees labels, not field names. The delivered message MUST use what the
reader saw.

- **R4.10** A name MUST be resolved in this order: an explicit label attribute on
  the control; the `<legend>` of the nearest enclosing `<fieldset>`; the
  control's `aria-label`; the text of an enclosing `<label>`; the text of a
  `<label for>` referencing it; finally the raw field name.
- **R4.11** When deriving a name from element text, nested controls, hints
  (`<small>`), option text and host-injected nodes MUST be excluded — so a label
  wrapping its own input reads as just the question.
- **R4.12** Control groups MUST collapse correctly: a lone checkbox is a boolean;
  several checkboxes sharing a name are a list of the checked values; radios are
  the single checked value or blank; a multiple `<select>` is a list.

### Unavailable browser affordances

The sandbox denies these. They fail *silently*, which is the worst failure mode,
so both requirements below are mandatory.

- **R4.13** A page MUST NOT rely on `window.open`, `window.prompt`,
  `window.alert`, `window.confirm`, or top-level navigation.
- **R4.14** The authoring guide MUST state this explicitly, because an agent will
  reach for them by habit (R2.44).

Substitutes the host MUST provide:

- **R4.15** An authored `<a href>` to an http(s) destination MUST work. The
  kernel MUST intercept the click and route it through the external-navigation
  capability. Same-document fragments MUST be handled locally.
- **R4.16** Anything needing a browser-level dialog MUST be built in the page, or
  requested through a capability that renders in host chrome.

### The `method="dialog"` trap

- **R4.17** A `<form method="dialog">` inside a `<dialog>` is still captured
  under R4.5, because the rule is deliberately unconditional. An author using a
  dialog form for a purely local confirm and forgetting the opt-out attribute
  **will send a message they did not intend**.
- **R4.18** This is accepted (the plain-HTML promise is worth more than the sharp
  edge) and MUST be called out prominently in the authoring guide.

## Uploads

- **R4.19** A captured form MAY contain `<input type="file">`, including
  `multiple`.
- **R4.20** On submit, files MUST be uploaded first, then the submission
  delivered referencing them. A partial failure MUST fail visibly and MUST NOT
  deliver a submission claiming files that were not stored.
- **R4.21** Stored filenames MUST be generated by the host. A reader-supplied or
  page-supplied name MUST NOT determine a path, so a hostile page cannot choose
  where bytes land.
- **R4.22** Files MUST land in the page's own uploads directory and be reported
  to the agent by path.
- **R4.23** Per-file and per-form limits MUST be enforced and documented.
  Recommended: 24 MiB per file, 8 files per form.
- **R4.24** Upload failures MUST be shown in the page's form status. They MUST
  NOT be silently dropped.

## Files the page shows

- **R4.25** A page references its own files relatively: `<img src="chart.png">`,
  `<link href="style.css">`, `<script src="app.js">`, including nested paths.
  This follows from R1.2 and R1.3 and requires no API.
- **R4.26** A page MAY `fetch()` its own files as data (R3.13).
- **R4.27** A host MUST NOT require an API call to construct a URL for the page's
  own file. *Informative:* the previous design needed one because assets lived on
  a separate origin; under this spec they do not.

## `window.threadPage`

The complete page-facing API. A host MUST provide exactly this and MUST NOT add
anything host-specific (P2, P4).

```js
window.threadPage = {
  version: 1,

  // Invoke one capability. Resolves with its result, rejects with an Error
  // carrying a `code` property from the fixed error set.
  invoke(method, params): Promise<Result>,

  // Poll a read capability. Returns a stop function. Pauses when the tab is
  // hidden. Calling the stop function ends all polling.
  watch(method, params, listener, { intervalMs }): () => void,

  // Protect in-page state from an automatic reload.
  setDirty(boolean): void,
};
```

- **R4.28** `invoke` MUST reject with a code from the fixed error set
  ([05-capabilities.md](./05-capabilities.md) §Errors), never with a bare string.
- **R4.29** Calls made before the channel is ready MUST be queued and flushed,
  not lost.
- **R4.30** `watch` MUST clamp its interval to a sane range, MUST pause while the
  document is hidden, and MUST stop polling when its stop function is called.
  A page that never calls `watch` MUST cause no polling.
- **R4.31** `watch` MUST deliver errors to the listener rather than throwing
  asynchronously.
- **R4.32** A response that does not match the expected shape MUST be rejected as
  invalid rather than passed through.
- **R4.33** The API MUST NOT grow a method that is only meaningful on one host.

## Read-only mode

- **R4.34** When a page is served from an offline copy, the host MUST disable
  captured-form controls, show a status line on each captured form, and show a
  banner the page cannot suppress.
- **R4.35** On reconnection the host MUST restore only the controls it disabled,
  leaving controls the page disabled itself alone.

## Design system

- **R4.36** The host MUST NOT impose a design. It MAY provide a starting
  stylesheet inside the seed, which the page then owns and may replace entirely.
- **R4.37** Each page MUST carry its own styling. Pages MUST NOT share a
  stylesheet, script, or component library, and the host MUST NOT provide a
  shared space for one. *Rationale:* per-page copies are what make restyling one
  page safe and host upgrades harmless. Consistency between pages is achieved by
  instructing the agents that write them, not by sharing a file.
- **R4.38** A page MUST be usable at narrow widths, in dark mode, and with
  reduced motion — as authoring guidance, not host enforcement.
